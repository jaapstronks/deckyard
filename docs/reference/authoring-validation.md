# Validation while authoring

A saved quality defect in prose must not prevent an unrelated edit from being stored. The whole-deck save compares each submitted slide with its own stored slide in the same language. `validateFieldChange` compares declared values by path: unchanged prose can retain a missing-value or length defect; changed prose must meet the field's rules. New slides, a changed slide type and new collection members receive strict validation. No author text is discarded to make a save pass.

This is a write policy, not a second content format. Field definitions still declare one limit. `validateSlideFields` without `previousSlide` remains the strict validator used for new content. The editor uses that strict check after a successful save to offer review of retained defects. Passing `previousSlide` is appropriate only when the writer has loaded the actual stored slide; never accept a caller's claimed previous value.

## Which rule belongs where

| Surface or value                                                         | Policy                                                                                                                                       | Implementation                                                               |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Descriptive image alternatives, including AI output                      | Normalize at declared word boundaries, at most 180 UTF-16 units; retain short descriptions                                                   | `field-normalization.js`, declared `overflow: 'truncate'`, LLM alt generator |
| Library metadata and picked-image alternatives                           | Normalize the language-keyed alt map on library writes, library form reads and image placement                                               | `normalizeAltMap`, `image-library.js`, `apply-pick.js`                       |
| Nested image collections                                                 | Recurse through declared fields with the same alt policy                                                                                     | `normalizeFieldContent`, storage slide normalization                         |
| Previously stored prose length or missing-value defect                   | Preserve the original value when unchanged at its stored path; allow other edits and offer review after saving                               | Whole-deck save service, `validateFieldChange`, `savedQualityIssues`         |
| New or changed author prose                                              | Enforce the declared limit; retain the editor buffer on refusal                                                                              | Field controls, strict field validation, save refusal                        |
| Untranslated prose                                                       | Permit missing translations; validate values that are present                                                                                | `allowMissingTranslationText`                                                |
| URLs, media references, enums, collection structure and undeclared keys  | Keep their validators; the stored-prose policy gives no exemption                                                                            | Field-type validators and declared-key checks                                |
| New imports and MCP slide creation/replacement                           | Normalize declared alt overflow, then validate new content strictly                                                                          | Import and slide services; shared storage normalization                      |
| Existing-deck writes through v1 or the editor                            | Apply the same whole-deck change policy                                                                                                      | `savePresentation`                                                           |
| Live collaboration                                                       | Keep document persistence through the storage facade and shared normalization; live transport does not use the editor's HTTP save-refusal UI | `server/collab/persistence.js`                                               |
| Authorization, conflicts, slide locks, unsafe links and storage failures | Refuse the affected write and keep an honest unsaved/error state                                                                             | Existing service and storage boundaries                                      |

The image library's alt form keeps generation, editing and the existing optional use-without-alt choice together. This policy introduces no new required alt field or publish gate. Library forms explain that overlong descriptions are shortened; the save manager also reports when it normalizes a description in an editor buffer. Existing stored values remain available in existing revision history where a revision contains them; no separate recovery store or destructive migration is introduced.

## Recovery and bug reports

A save refusal never selects a slide or changes language automatically. The save banner names the failing language, slide and field. Its explicit recovery action opens the in-memory version without attempting another failing save, retaining the current version's pending edits. Field-local diagnostics continue to appear when that field is shown.

Every failed save also offers an expandable, read-only bug-report text field. It captures the failure-time URL, timestamp, presentation id, revision, active language, selected slide, browser, full message, API code, HTTP status, details and stack when available. Copy uses the shared clipboard helper; if copying fails, the text field receives focus and selects its contents for manual copying. The report is shown locally and is sent only when the author chooses to report it. It does not include the deck body, credentials or request headers.

The save status says saved only after the server acknowledges the write. Retained-quality notices describe saved work separately from a refusal. Do not replace a write failure with a successful status just because its input still exists in memory.

## Verification

`tests/service-layer-presentation-save.test.js` exercises the save manager against the real HTTP handlers with the database double, including a seven-item Dutch/English timeline with an old overlong English date, append/remove, reload and refusal of a new invalid date. `tests/field-change-validation.test.js` covers unchanged prose versus types, links, machine values, nested collections and new members. `tests/editor-save-feedback.test.js` checks focus/URL/buffer preservation, explicit recovery, complete reports, blocked clipboard fallback and saved-quality notices. Alt normalization tests cover idempotence and recursive collections.
