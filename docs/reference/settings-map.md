# Settings map: scopes, controls and configuration

Snapshot: Deckyard **1.77.2 plus commit `6ff79f0b`**, inspected on 2026-10-20. This reference describes the current `/settings` page, its fourteen tabs and their persistence and authorization boundaries. Theme and slide-type editor internals are separate workbenches; their management actions are listed here.

## Scope and access

The settings menu groups tabs as personal, Designer and Admin. Those groups describe visibility, not storage scope. The [tab registry](../../client/views/settings/tab-registry.js) is the source of truth: inaccessible tabs are hidden, unknown or inaccessible hashes resolve to Account, and Organization and Members appear with the personal tabs for a non-admin who can reach them. API Keys additionally requires the `publicApi` installation feature. [Page access](../../client/views/settings/index.js) is calculated when the page mounts.

| Term                                       | Persistence and API boundary                                                                                                                                               | Who can write                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Personal**                               | Instance-wide `user_settings` for one person, keyed primarily by stable user ID with an email fallback. `GET/PUT /api/settings/me`; not scoped to the active organization. | An authenticated user with an email writes their own preferences. See [settings storage](../../server/storage/settings.js) and [settings routes](../../server/routes/api/settings.js).                                                                                                                                                                                                                                                                             |
| **Instance**                               | Singleton `app_settings`; shared by all organizations. `GET/PUT /api/settings/app`. Email template overrides and their default locale also have instance-wide tables.      | App settings and template writes require the instance `isAdmin` flag. App reads require authentication; webhook settings are removed for non-admin readers. See [settings routes](../../server/routes/api/settings.js) and [template storage](../../server/storage/email-templates.js).                                                                                                                                                                            |
| **Organization policy**                    | Active organization's `organizations.settings`, exposed by `GET/PATCH /api/settings/organization`.                                                                         | Keys other than `disabledSlideTypes` require instance admin and, in multi-organization mode, admin/owner membership in that organization. `disabledSlideTypes` requires designer capability. AI translation instructions additionally require `ai`. See [settings routes](../../server/routes/api/settings.js).                                                                                                                                                    |
| **Organization records**                   | Organization profile, memberships, custom fonts, custom themes and custom slide types are separate records.                                                                | Profile edits require organization admin/owner; deletion requires owner. Membership actions have their own role rules. Font/theme/custom-type mutations use server `canManage`: `isDesigner`, or instance admin as a fallback only in single-organization mode. See [organization routes](../../server/routes/api/organizations.js), [member routes](../../server/routes/api/organization-members.js) and [designer gate](../../server/utils/route-middleware.js). |
| **Personal API access in an organization** | API keys are filtered by both `organization_id` and caller `owner_email`.                                                                                                  | The key API requires authenticated email, while the Settings tab is restricted to the menu's Admin gate. See [key routes](../../server/routes/api/api-keys.js) and [key storage](../../server/storage/api-keys.js).                                                                                                                                                                                                                                                |

The menu's Admin gate uses [`isOrganizationAdmin`](../../shared/organization-role.js): instance admin, narrowed by active admin/owner membership when present. This differs from the backend's instance-only check for app settings, templates and instance health. Organization ownership alone permits profile and membership operations but does not grant access to organization policy keys that also require instance admin.

`defaultThemeId` and `enabledThemes` belong exclusively to **organization policy**. Sending either to `PUT /api/settings/app` is rejected. A designer can open Themes and manage custom records, but the currently displayed default/visibility controls still require the organization-policy admin gate to save.

## Presentation settings

Presentation settings belong to the deck and require write access to that deck. The editor's **Deck settings** modal saves changes as they are made; text fields generally save on blur. Tags use their own immediate save request. The modal has no independently addressable route. See the [modal composition](../../client/views/editor/modals/settings-modal/index.js#L47) and [shared save service](../../server/services/save-presentation.js#L16).

## API exposure and limitations

Locally launched stdio MCP has no API key and runs as an operator with direct database access. See [v1 authentication scope](../../server/routes/public-api/v1/middleware.js#L99), [MCP deck access](../../server/mcp/presentation-access.js#L42) and [MCP policy](../../server/mcp/authorization.js#L111).

## Installation environment inventory

Environment variables configure the installation and are set by its operator. They are not user-account preferences. Existing process variables take precedence over the local environment file, as implemented by the [environment loader](../../server/config/env.js#L28). The canonical list, descriptions, defaults and constraints are in [`.env.example`](../../.env.example); the [manifest test](../../tests/env-manifest.test.js#L2) checks that engine reads remain documented. Variable names below are grouped for navigation; no deployment values are reproduced.

Theme defaults and allowlists can be overridden by stored organization settings. Analytics retention variables seed the values subsequently managed through instance settings. External analytics providers have documented environment fallbacks. Infrastructure credentials, bind addresses, database/storage configuration, proxy policy, browser executables, timeouts and debug controls remain deployment configuration. Raw analytics head snippets and Google Tag Manager are explicitly environment-only.
